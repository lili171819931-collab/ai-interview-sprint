# 二、专家思维链（必须按此推理，禁止跳步）

## Chain 0 · 一句话定位
先回答：
「这是导航站，还是选型决策台？」
标准答案：选型决策台——降低信息搜集成本，把主观体验变成可审计判断。

## Chain 1 · 问题定义（5 Why 压缩版）
对每个核心功能问：
1. 用户此刻要完成什么任务？
2. 现在用什么笨办法？
3. 失败成本是什么（选错工具/说不清理由）？
4. 我们最小可证明的价值是什么？
5. 哪些看起来很酷但并不服务该任务？

输出：一张「任务-痛点-价值-非目标」表。

## Chain 2 · AI 功能值不值得做（六闸门）
任何“上 AI”的想法必须过闸：
1. 用户价值：是否缩短选型时间或提高解释力？
2. 模型能力：是否真需要生成，还是结构化检索/对比即可？
3. 数据条件：是否有合规可得、可持续更新的来源？
4. 链路适配：是否可拆成抓取/校验/展示/降级，而不是黑盒？
5. 成本收益：维护 seed + 公开源 是否低于自动全网爬取幻觉成本？
6. 迭代节奏：是否能周更/日更验证，而不是一次性炫技？

本项目默认立场：
- 不做模型自动评分改写
- 做公开源日更 + 人工评分底座 + 可追溯对比
- AI 可用于辅助摘要/报告，但必须标注“辅助”且可关闭

## Chain 3 · 范围冻结（Must / Should / Won’t）
Must（不可砍）：
- 日更管线与失败降级
- 工具介绍结构化
- 优劣势对比可追溯（维度+证据+来源）
- 来源报告与方法口径页
- 可演示不白屏

Should（可后置）：
- 报告导出 PDF
- 场景模板
- 埋点与个性化
- 企业私有工具库

Won’t（明确不做）：
- 伪科学唯一总榜
- 需登录违规抓取
- 账号社区与实时军备竞赛

## Chain 4 · 数据产品化思维
信息 → 资产 → 决策：
公开源登记
→ 抓取与解析
→ Zod 契约校验
→ 原子写入 daily-bundle
→ live-fetch-report 审计
→ 页面按 freshness 降级展示
→ 对比结论只给场景建议

硬规则：
- seed 是事实与评分底座
- RSS 可更新 changelog/看点，不可改七维分
- inferred 来源禁止打极端分
- 校验失败保留昨日快照

## Chain 5 · 决策表达思维
对比输出必须遵循：
候选集 → 关键指标（综合/成本/企业/上手）→ 雷达/柱状图 → 智能摘要 → 跨品类风险警告 → CTA（去详情/看来源）
禁止：无场景总冠军、无证据口号、堆砌统计卡片破坏首屏。

## Chain 6 · 商业与落地思维
阶段：
P0 个人/团队效率工具
P1 导出报告 + 场景模板
P2 企业选型台（权限/审计/内部工具库）
P3 行业情报与 API

每个阶段必须回答：
谁付钱、付什么、缺什么就不能卖。

## Chain 7 · 复盘思维
每个里程碑结束写：
做成了什么 / 砍了什么 / 风险如何兑现 / 下一周只做一件事。

# 三、全量风险清单（执行时逐条勾选）

## R1 产品风险
| 风险 | 影响 | 触发信号 | 缓解 | 验收 |
|------|------|----------|------|------|
| 做成导航站而非决策台 | 无差异化 | 首屏只有链接列表 | 强化搜索→对比→来源链路 | 3 分钟内可完成一次对比决策演示 |
| 伪排名误导用户 | 信任崩塌 | 出现唯一总榜 | 只做场景建议 | 对比页无“第一名”文案 |
| 功能膨胀 | 延期 | Should 混入 Must | 每周砍需求 | README 非目标清晰 |

## R2 数据风险
| 风险 | 影响 | 触发信号 | 缓解 | 验收 |
|------|------|----------|------|------|
| RSS/源失效 | 日更空洞 | successCount 骤降 | 多源+离线刷新+报告页 | 单源失败不阻断整体 |
| 解析脏数据 | 错误展示 | title 为空/HTML 残留 | CDATA 处理+Zod | refresh 校验失败不写盘 |
| 覆盖昨日好数据 | 线上回退难 | 直接覆写 bundle | 原子写+失败保留 | 故意造坏数据验证保留 |

## R3 可信度风险
| 风险 | 影响 | 触发信号 | 缓解 | 验收 |
|------|------|----------|------|------|
| 评分过主观 | 争议大 | 无 evidence | 强制证据与来源等级 | 详情页可见证据 |
| 抓取自动改分 | 不可审计 | 脚本写 scores | 代码层禁止 | code review/脚本检查 |
| 跨品类硬比 | 错误结论 | 聊天模型 vs 视频工具无提示 | 风险警告卡 | 跨品类对比有 warning |

## R4 技术风险
| 风险 | 影响 | 触发信号 | 缓解 | 验收 |
|------|------|----------|------|------|
| 契约漂移 | 页面运行时炸 | 字段类型不一致 | Zod + 构建 | npm run build 通过 |
| 缓存冲突 | dev 500 | build/dev 混用 | 清 .next 重启 | 本地可打开 |
| 图表不可读 | 决策失败 | 无语义色/无结论 | 语义色+摘要 | 对比弹窗 10 秒读懂 |

## R5 合规风险
| 风险 | 影响 | 触发信号 | 缓解 | 验收 |
|------|------|----------|------|------|
| 违规抓取 | 法律/封禁 | 需登录源 | 仅公开 RSS/Atom/Changelog | 源列表可审计 |
| 密钥入库 | 泄露 | .env 进 git | gitignore + 审查 | 无密钥文件 |
| 不当商用声明 | 品牌风险 | 声称官方认证 | 文案降级为研究看板 | README 声明边界 |

## R6 体验风险
| 风险 | 影响 | 触发信号 | 缓解 | 验收 |
|------|------|----------|------|------|
| 筛选过复杂 | 弃用 | 首屏控件过多 | 主搜索+品类段+更多折叠 | 目录页 1 眼可搜 |
| 空结果无助 | 流失 | 无推荐 | 热门/更新推荐 | 空态有下一步 |
| 移动端不可用 | 演示失败 | 横向溢出 | 响应式验收 | 手机可完成对比 |

## R7 交付风险
| 风险 | 影响 | 触发信号 | 缓解 | 验收 |
|------|------|----------|------|------|
| 文档与代码不一致 | 面试穿帮 | 路由/字段对不上 | 验收清单对页 | 演示脚本可跑通 |
| 双仓不同步 | 源码迷路 | 只更一边 | PATH-MAP+子模块 | 两边路径可打开 |
| 演示断点 | 叙事失败 | 无网/stale | offline徽章+离线命令 | stale 仍可讲解 |

## R8 商业风险
| 风险 | 影响 | 触发信号 | 缓解 | 验收 |

# 四、决策闸门（每次加需求先过）

Gate A · 用户任务闸门：是否直接服务“形成候选集/做对比/核来源”？
Gate B · 可信闸门：结论能否指出证据与来源等级？
Gate C · 可运维闸门：失败时能否降级且不毁掉昨日数据？
Gate D · 可演示闸门：3 分钟能否讲清价值与风险？
Gate E · 商业闸门：是否为下一阶段收费创造必要资产（数据/报告/模板）？

任一 Gate 失败 → 降为 Should/Won’t，或改成文档说明而非开发。
