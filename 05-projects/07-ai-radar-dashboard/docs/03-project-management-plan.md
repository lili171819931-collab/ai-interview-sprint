# 项目管理计划（Project Management Plan）

## 1. 工作分解（WBS）

1. 需求与范围冻结
2. 设计系统与 IA
3. 前端页面开发
4. 数据管线开发
5. 测试与验收
6. 上线与运维文档
7. 演示与复盘

## 2. 里程碑与交付物

| 里程碑 | 交付物 | 完成判定 |
|--------|--------|----------|
| M1 需求冻结 | 立项书 + 需求冻结 | 需求边界明确 |
| M2 设计完成 | IA + 设计系统 + 图表规范 | 页面结构可实现 |
| M3 开发完成 | 页面/组件/脚本 | 本地可运行 |
| M4 测试完成 | QA 报告 + 验收清单 | 关键流程通过 |
| M5 闭环完成 | 来源报告 + 运维手册 + 复盘 | 可持续迭代 |

## 3. 角色与职责（RACI 简版）

- 产品（A/R）：需求、优先级、验收标准
- 设计（R）：页面体验、可视化规范
- 研发（R）：前端实现、数据脚本、性能
- QA（R）：测试执行与缺陷记录
- 评审（C）：体验与业务可讲性反馈

## 4. 风险管理

| 风险 | 影响 | 应对 |
|------|------|------|
| 公开源失效 | 日更不完整 | 单路失败跳过 + 快照保留 |
| 评分争议 | 决策不信任 | 证据字段 + 来源等级 + 口径页 |
| 设计复杂化 | 可维护性下降 | 组件化与语义 token |
| 构建冲突 | 环境不稳定 | build/dev 分离，重启清缓存 |

## 5. 变更管理

- 新需求进入待办池，按 Must/Should 分类。
- 影响数据契约的变更必须更新 `data-contract.md`。
- 页面信息结构变更必须更新 `ia.md` 与 `README`。

## 6. 沟通节奏（建议）

- 每日：状态更新（完成/风险/下一步）
- 每阶段：演示与验收同步
- 收尾：复盘与下阶段 backlog 冻结
