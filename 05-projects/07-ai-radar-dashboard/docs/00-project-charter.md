# 项目立项书：智衡 AI Radar

## 1. 项目背景

AI 平台与工具更新速度快，公开信息碎片化。目标用户（产品经理、工程师、解决方案人员）需要一个可追溯的日更看板，而不是主观排行榜。

## 2. 项目目标

- 建设可运行 Web 看板，覆盖总览、目录、对比、来源报告、方法口径、**机会简报**。
- 建立公开源日更管线，支持失败降级与快照保留。
- 固化七维评分与证据体系，保证可解释与可审计。
- 形成「雷达发现 → 今日构建建议」的行动层（BuilderPulse 对齐，许可合规）。
- 形成可用于面试展示的完整项目闭环文档。

## 3. 成功标准（Definition of Success）

- 功能：核心页面可访问并可演示（含 `/pulse` 机会简报）。
- 数据：`data:refresh` 可拉取公开源并落地 `daily-bundle`、`live-fetch-report`、`builder-pulse-daily`。
- 可信：评分不被自动抓取改写；来源等级可追溯；第三方内容有署名与 NC 边界。
- 工程：`npm run build` 通过；异常场景有降级策略。
- 包装：需求、设计、项目管理、研发测试、上线复盘文档完整（含 `docs/14` 本轮迭代）。

## 4. 范围边界

### In Scope
- AI 工具目录、对比分析、来源报告、方法说明。
- 公共 RSS/Atom/公开 Changelog 数据聚合。
- 设计系统、图表组件与商务化视觉升级。

### Out of Scope
- 用户登录、权限系统、付费体系。
- 需要登录态或违规抓取的数据源。
- 实时秒级行情与自动评分改写。

## 5. 关键干系人

- 业务 Owner：产品经理（lili）
- 产品与设计：本项目文档与页面信息架构负责人
- 研发：Next.js 前端 + 数据脚本
- 评审视角：面试官 / 项目评估者

## 6. 核心里程碑

1. 需求冻结与数据契约确认
2. 页面 MVP 打通（总览/目录/详情/对比/口径）
3. 日更管线接入与降级策略完成
4. 商务化设计与图表体系完成
5. 测试验收、演示脚本、复盘归档

## 7. 风险摘要

- 公开源可用性波动：以降级和快照保留应对。
- 评分主观性争议：以来源等级 + 证据字段应对。
- 视觉过度炫技：坚持“信息优先，图表服务结论”。
