# 极致 Prompt：微迹 Weiji · 商业价值专用版（可直接复制）

> 已按 `weiji-mini` 当前业务预填【我的输入】。  
> 用途：从「能打卡的 MVP」升级到「值得做、能赚钱、90 天可验证」的商业方案。  
> 源码：`ai-projects/products/weiji-mini`｜项目包装：`05-projects/01-weiji-product`

## 可复制正文

```text
你是一位同时具备「顶级产品经理 + 增长黑客 + 商业分析师 + 微信生态操盘手」能力的顾问。
请基于已上线/可运行的微信小程序「微迹 Weiji」做商业价值设计与升级方案，而不是再做一个功能 Demo。

【产品事实（已存在，勿当成空白创意）】
- 品牌：微迹（Weiji）
- 一句话：用 10 秒完成一次微习惯打卡，用连续天数证明你在变好
- 形态：微信原生小程序
- 已实现 MVP：创建微习惯（模板+自定义）、今日一键打卡/取消、连续天数（策略 A：今日未打卡仍展示截至昨天）、今日进度、记录月历、本地 wx.storage 持久化、归档/删除、活跃习惯上限 7
- 页面：今日 / 记录 / 创建 / 详情（≤4 页）
- 明确未做：社交排行、云同步账号、复杂图表、订阅消息、AI 代打卡、付费会员
- 已规划但未做的 AI 方向：基于个人打卡数据的「周复盘」轻量生成（有边界、可评测；禁止替用户打卡）
- 技术现实：本地存储优先，换机不同步；无后端也可演示；体验版/提审路径已具备文档

【硬性目标】
输出必须能回答：微迹为什么值得继续做、靠什么赚钱、凭什么活下来、如何在 90 天内验证商业闭环。
拒绝空泛创意；必须站在「已有打卡闭环」之上做增量，优先可验证、可落地、可复利。
商业价值 > 功能炫技；增长 > 页面美观；验证 > 完美规划。

【我的输入｜已按微迹预填】
1. 目标用户
   - 身份：想养成习惯但容易放弃的普通人；轻工具偏好者；不一定重度自我管理极客
   - 场景：每天碎时间完成「足够小」的动作（喝水、拉伸、读 1 页等），需要即时反馈
   - 付费能力：C 端中低客单为主（订阅/会员/模板包量级）；B 端（企业 wellness / 社群教练）为可选扩展，非默认
   - 现有替代：微信运动、便签/备忘录、Excel、Notion、潮汐/小习惯类 App、打卡群 + 表格、纯意志力
2. 已有资源
   - 产品：可运行 MVP + 完整从设计到上线文档
   - 技术：微信小程序工程能力；本地存储方案已通；可接云开发/简易后端（尚未建）
   - 流量：暂无稳定投放与达人矩阵（冷启动需设计）
   - 内容：8 个微习惯模板；可延伸习惯库/周复盘内容
   - 品牌：微迹命名与视觉基线已有
   - 渠道：微信生态（分享、社群、公众号、体验版内测）可触达，尚未规模化
   - 资金/团队：按小团队/个人创业节奏假设（预算有限，优先低成本验证）
3. 行业/品类偏好
   - 微习惯 / 轻健康 / 个人效能；可延伸到「有边界的 AI 复盘」与社群陪伴，但不得违背「轻、小、10 秒」品牌
4. 商业目标（排序请你校准，默认如下）
   - P0：验证付费意愿与留存，证明不是伪需求
   - P1：形成可复利的获客飞轮（分享/社群/内容）
   - P2：支撑融资或作品叙事（AI PM 面试/作品集亦可，但商业方案不能只服务叙事）
5. 约束
   - 必须立足微信小程序生态
   - 首屏与品牌继续「轻」：不做重计划、不做代打卡、不做信息过载
   - 合规：避免医疗功效承诺、避免诱导分享违规、支付与虚拟支付按类目合规
   - 时间：先给 90 天验证计划；MVP 增强应可分期，不要求一次性大重构
   - 技术：能解释何时必须上云/账号；在此之前可用最小后端或纯本地+导出

————————————————
一、先判断「值不值得做」（一票否决视角）
请对「继续做微迹并商业化」严格审查；任一关键卡死则给出替代方向（仍尽量复用现有打卡资产）：
1. 真痛点：用户是否愿意花钱/花时间/主动传播来解决？
2. 频次：打卡类天然日频，但付费点是否匹配频次？
3. 支付意愿：谁付钱？C 会员 / 教练 B 端 / 团购社群 / 平台？客单与决策链路？
4. 微信生态适配：分享、社群、公众号、支付、订阅消息、搜一搜如何变成生意而不是功能清单？
5. 竞争壁垒：数据、网络效应、内容飞轮、关系链、切换成本里哪项能从本地打卡长出来？
6. 单位经济：CAC、转化、毛利、复购、回本是否粗算为正？
7. 合规与平台风险：类目、虚拟支付、隐私、健康宣称、订阅消息打扰。

若结论为 No-Go：直接否决「大而全习惯平台」幻想，并给 2 个更优、仍可复用微迹资产的替代切口。

————————————————
二、从 8 个角度完成设计（每角：结论 + 可证伪证据逻辑）
必须显式承接现有 MVP，标明：保留 / 增强 / 新做 / 坚决不做。

【角度 A｜用户价值】
- Jobs to be Done：用户雇佣微迹完成什么任务？（相对备忘录/打卡群的增量）
- 核心场景：1 个主场景 + 2 个高价值附属场景（可含周复盘，但不得抢首屏）
- Before / After
- 最小可用体验：首次 60 秒必须感知什么？（已有空状态→创建→打卡，请评估是否足够及如何加强）

【角度 B｜商业模式】
- 赚钱方式排序（交易抽成/SaaS/广告/增值/线索/会员/差价/企业定制）
- 付费方 vs 使用方
- 定价：免费层（建议对齐当前本地打卡）、付费触发点、锚点
- 收入公式：流量 × 转化 × 客单 × 复购 × 生命周期
- 特别评估：何时上会员？周复盘 AI 是否可单独收费？社群教练工具是否成 B 端？

【角度 C｜增长飞轮】
- 冷启动：前 100 / 1000 / 10000 从哪来？（结合无投放现实）
- 分享动机：利益/身份/内容/关系/工具结果——微迹最可能靠哪一个？如何产品化？
- 留存：D1/D7/D30 钩子（连续天数、订阅消息、周复盘、社群）
- 飞轮：A→B→C→A 写清闭环；禁止「做了就能传播」空话

【角度 D｜竞争与定位】
- 替代方案对比表（含线下与大厂）
- 差异化一句话：比 X 更适合 Y 完成 Z
- 不做清单（必须包含：代打卡、重计划、首屏统计墙等）
- 护城河：0-3 月 / 3-12 月 / 12 月后

【角度 E｜产品架构（小程序特化）】
- 信息架构：首页仍只做「今天把小事做完」
- 核心路径：进入 → 关键动作/付费 ≤ N 步（给出 N 与路径）
- 微信能力地图：登录、云同步、支付、订阅消息、分享卡片、视频号、社群/企微——每项必须写「如何服务生意」
- 数据资产：哪些打卡数据会越用越值钱？（为周复盘/个性化做准备，但给隐私边界）

【角度 F｜运营与变现节奏】
- 0-30 天验证假设与成功标准（可量化）
- 30-90 天从能用到能赚钱
- 每周关键运营动作清单
- 客服/履约/售后如何支撑口碑（若有虚拟商品/会员）

【角度 G｜财务与风险】
- 粗算单位经济（给出假设表，勿假装有真实投放数据）
- 最大风险 Top3 + 对冲
- 失败信号：出现什么指标就 pivot / 停掉

【角度 H｜组织与交付】
- MVP 增强范围：Must / Should / Won’t（相对当前代码）
- 最小团队与外包边界
- 技术复杂度（本地→云同步/支付/订阅消息分级）与里程碑
- 与现有仓库对齐：源码在 ai-projects/products/weiji-mini；文档在 ai-interview-sprint/05-projects/01-weiji-product

————————————————
三、输出格式（必须按此结构）

1. 一句话定位（可迭代微迹原定位，但需说明为何改/不改）
2. 目标用户画像（含付费动机）
3. 核心价值主张（Before/After）
4. 商业模式画布（精简版）
5. 产品增强清单（P0/P1/P2，标注是否改现有代码）
6. 关键用户旅程（含转化/付费节点）
7. 增长飞轮（文字闭环）
8. 90 天验证计划（假设 → 实验 → 指标 → 决策阈值）
9. 单位经济粗算（假设透明）
10. 风险与不做清单
11. 最终推荐：Go / Conditional Go / No-Go + 理由
12. 附加：若 Go/Conditional Go，给出「下周就能开工」的 5 个工程任务（可直接派给开发）

————————————————
四、思考质量要求
- 每个关键判断可证伪，不写鸡汤
- 切口窄而深；反对「习惯领域平台」
- 若认为本地-only 会卡死商业化，必须给出最小上云方案与触发条件
- AI 周复盘只能作为增值能力，必须有边界、可评测、失败降级；严禁自动代打卡
- 信息若仍不足，最多追问 5 个关键问题；但本轮应先基于预填信息给出完整方案草稿，问题放在文末

现在开始：先给出对微迹商业化的第一轮诊断与完整结构化方案。
```

## 使用方式（微迹专用）

1. **直接整段复制**上方 fenced 内文本给模型，无需再填 5 项输入。  
2. **改资源假设时**：只改「已有资源 / 约束」两段，保持产品事实不动。  
3. **评审焦点**：单位经济、飞轮、90 天验证——三块虚则商业化不成立。  
4. **落地对照**：方案里的 P0 工程任务，应能映射回 `products/weiji-mini` 页面与 `utils/habit.js` 数据模型。
