# 01 · 产品需求（PRD）

## 1. 定位

| 项 | 内容 |
| --- | --- |
| 品牌 | 微迹（Weiji） |
| 一句话 | 用 10 秒完成一次微习惯打卡，用连续天数证明你在变好 |
| 品类 | 微信小程序 · 微习惯打卡 |
| 阶段目标 | 2 小时可演示 MVP → 体验版内测 → 可提审上线 |

## 2. 问题与洞察

- 用户想养成习惯，但传统打卡 App 太重、步骤多、容易放弃。
- 「足够小的动作」+「即时反馈」比复杂计划更能形成闭环。
- MVP 先证明「今天做完小事」成立，再谈 AI / 社交 / 云同步。

## 3. 目标用户

- 想养成习惯但容易半途而废的普通人
- 不喜欢沉重工具的轻量用户
- 需要「做了就有反馈」的即时满足型用户

## 4. 核心场景（主路径）

1. 首次进入 → 空状态引导创建第一个微习惯  
2. 今日列表看到待打卡项  
3. 一键打卡 → 进度与连续天数更新  
4. 误点可取消今日打卡  
5. 记录页回顾历史  
6. 详情中编辑 / 归档 / 删除  

## 5. 范围

### Must

- 习惯 CRUD（创建、编辑、归档/删除）
- 今日打卡 / 取消打卡
- 连续天数、今日进度
- 历史记录（月历）
- 本地持久化
- 空状态与错误提示

### Should（有时间）

- 习惯颜色/模板
- 轻动效与震动反馈
- 提醒开关占位

### Won’t（本阶段不做）

- 社交排行、云同步账号、复杂图表  
- 订阅消息推送、AI 推荐、付费会员、社区  

> AI 能力单独落在 [`../02-ai-weekly-insight/`](../02-ai-weekly-insight/)，不塞进 MVP 首屏。

## 6. 成功标准（产品 Done）

- [ ] 新用户 2 分钟内完成「创建 + 首次打卡」
- [ ] 打卡操作 ≤ 1 次主点击（取消需确认）
- [ ] 连续天数规则可解释、实现与文档一致
- [ ] 可体验版分发给 ≥1 位外部测试者
- [ ] 具备提交微信审核所需的基础完整性（无死链、无游客依赖）

## 7. 关键指标（上线后观察）

| 指标 | 定义 | 早期目标 |
| --- | --- | --- |
| 激活打卡率 | 当日创建习惯且完成 ≥1 次打卡的用户占比 | ≥ 60% |
| D1 回访 | 次日打开并进入今日页 | 观察即可 |
| 人均活跃习惯数 | 未归档习惯数 | 建议 1–3，硬上限 7 |
| 取消打卡率 | 取消 / 打卡 | 异常偏高则检查误触 |

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 范围膨胀 | 页面 ≤4；Won’t 写死 |
| streak 争议 | 选定策略 A 并文档化 |
| 游客 AppID 无法分发 | 上线路径强制正式 AppID |
| 本地数据丢失 | 明示本地存储；后续再做导出/云同步 |
