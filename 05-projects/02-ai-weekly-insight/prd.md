# PRD：微迹 AI 周复盘（Weiji Weekly Insight）

## 1. 背景与问题

- **用户是谁**：已在微迹建立 ≥1 个活跃习惯、有连续或断续打卡记录的轻量自律用户（学生 / 职场人），追求「小动作可坚持」，排斥复杂计划 App。
- **现在怎么做（现状）**：微迹已支持创建习惯、今日打卡/取消、连续天数、月历记录；但「记录」偏查询，用户很难从数据里看出「这周到底发生了什么、下一步该轻调什么」。
- **痛点**：
  1. 有数据、无洞察：看得到打了几天，看不懂节奏与断点原因模式
  2. 外部 AI 聊天无产品上下文：用户要手动描述习惯，且模型易给「大而全计划」
  3. 若乱加 AI：容易变成催促/代打卡，破坏「10 秒亲手完成」的产品承诺
- **为什么现在做**：0→1 打卡闭环已成立（见 `ai-projects/products/weiji-mini`）；下一步最值得验证的是「AI 能否在不破坏轻量感的前提下提高周留存与主动复盘率」。

## 2. 目标

- **业务目标**：提升 7 日留存与周活跃；提高「看过复盘」用户的次周打卡完成率。
- **用户目标**：每周用 ≤2 分钟看懂自己的微习惯节奏，获得 1 条可执行的轻建议（可忽略）。
- **非目标（不做清单）**：
  - ❌ 替用户自动打卡 / 补打卡
  - ❌ 生成多周复杂习惯计划或训练营
  - ❌ 社交对比排行（易引发焦虑，偏离微习惯）
  - ❌ 医疗/心理诊断式结论
  - ❌ 无打卡数据时硬编「本周表现很好」

## 3. 成功指标

| 指标 | 基线 | 目标（试点 2–4 周） | 统计口径 |
|------|------|---------------------|----------|
| 周复盘打开率 | 0 | ≥40%（有资格用户） | 本周有 ≥3 天活跃的用户中，打开复盘页占比 |
| 复盘完成率 | 0 | ≥70% | 打开后读完/点「知道了」或产生有效停留 ≥20s |
| 建议采纳率 | 0 | 15%–30% | 点击「采用本周轻建议」或手动改习惯标题/归档等 |
| 次周打卡完成率 uplift | 对照 | +5～10pct | 看过复盘 vs 未看过（同活跃度分层） |
| 有害体验投诉 | — | ≈0 | 「乱说我没打卡」「催我太多」「替我打卡」类 |

详细评测见 [`metrics.md`](metrics.md)。

## 4. 核心场景（1 主 + 2 附属）

### 主场景：周日晚 / 用户主动查看「本周复盘」

- **触发**：进入「记录」页出现「本周复盘」入口；或周日 20:00 订阅消息（可选，需授权）。
- **关键路径**：打开复盘 → 看到本周数据摘要（规则计算，可信）→ 阅读 AI 洞察（有据）→ 看到 1 条轻建议 → 结束或点「换一条更克制的建议」。
- **完成定义**：用户理解本周完成情况，且清楚建议来自本人数据；不要求必须采纳。

### 附属场景

1. **数据不足态**：本周打卡天数 &lt; 2：不生成「假繁荣」洞察，只给鼓励创建/完成第一次打卡的固定文案（规则，不调模型）。
2. **断 streak 安抚**：检测到某习惯连续中断：洞察强调「微习惯允许重启」，禁止羞辱语气；可建议「把标题改得更小」但需用户确认才改。

## 5. 解决方案

- **总体方案**：**结构化事实层（规则） + 受限生成层（LLM）**  
  - 事实层：完成率、各习惯打卡天数、最长连续、断点日期 —— **100% 由本地/服务端规则算出，模型不可改数**  
  - 生成层：基于事实 JSON + 少量历史摘要，生成「洞察段落 + 1 条轻建议」  
  - 本质是 **个人数据 grounding**（RAG 的产品形态：检索/注入的是自己的 checkIns/habits，不是企业文档）
- **为什么不是纯规则**：规则可做统计卡片，但「如何用一句话说清节奏、给出不伤体验的轻建议」需要语言生成；又必须锁死数字防止幻觉。
- **为什么不是 Agent**：不授权模型调用「打卡/删除/改数据」工具；最多提供「用户确认后才执行」的建议按钮。
- **关键流程**：

```
资格判断（本周数据是否足够）
  → 规则引擎生成 Fact Card（数字真相）
  → 组装 Prompt（系统约束 + Fact JSON + 风格：松柏绿气质/短句/不评判）
  → LLM 生成 Insight（必须引用 Fact 中的数字）
  → 校验器：数字一致性 / 违禁（代打卡、医疗、羞辱）/ 长度
  → 失败则降级为「仅展示 Fact Card + 固定鼓励文案」
  → 展示：事实卡片在上，AI 文案在下，标注「由你的打卡生成」
```

## 6. 边界与风险

- **拒答/降级策略**：数据不足、校验失败、模型超时 → 只展示规则事实，不展示 AI 段落。
- **转人工策略**：C 端无客服工单；用「反馈不准」按钮收集坏案例进入黄金集。
- **幻觉/错答处理**：数字以 Fact Card 为准；UI 上 AI 文案不得单独展示无来源数字；校验失败整段丢弃。
- **权限与合规**：
  - MVP 可本地拼事实 + 云函数调模型（仅上传脱敏统计，不上传多余个人信息）
  - 明确告知用户「生成需联网」；可关闭 AI 复盘
  - 不把打卡数据用于广告画像（产品承诺）
- **成本护栏**：每用户每周默认 ≤2 次生成（含「换一条」）；超限只读缓存；单次超时 8s；优先小模型。

## 7. 版本计划

- **MVP（可讲清 / 可原型）**：
  - Fact Card + 单次周复盘生成 + 校验降级 + 数据不足态
  - 不接订阅消息；入口放在记录页
- **v1**：
  - 订阅消息提醒、建议「一键变小习惯标题」（二次确认）、坏案例回流、A/B 文案语气
- **以后再说**：
  - 多周趋势对比、习惯模板推荐市场、端侧小模型

## 8. 依赖与协作

- **工程**：小程序记录页入口；事实统计复用 `habit.js` 规则；云函数/网关调模型；结果缓存
- **数据/知识**：`habits` + `checkIns`（见 weiji 数据模型）；无外部知识库
- **模型供应商**：任意合规国内/国际 LLM API；经统一网关更好（面试可讲平台化演进）
- **运营**：维护黄金集（晒图/吐槽/断签场景）；周报复盘准确率
- **安全合规**：隐私政策更新「AI 生成与数据上传范围」；未成年人语气约束（不做诊断）

## 9. 与微迹品牌的一致性检查

| 微迹原则 | AI 复盘如何遵守 |
|----------|-----------------|
| 10 秒打卡 | 复盘独立入口，不挡今日主路径 |
| 亲手完成 | 禁止代打卡 |
| 轻量 | 每周一次、短文案、一条建议 |
| 本地可运行基线 | MVP 可先「统计本地 + 生成可选」 |
