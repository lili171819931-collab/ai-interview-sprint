# 架构说明：微迹 AI 周复盘（产品视角）

## 架构草图

```
[微信小程序 · 记录页]
   │  入口：本周复盘
   ▼
[资格 & 本地事实层]
   │  复用 weiji 规则：habit.js / date.js / storage
   │  输出 Fact Card（纯计算，可信）
   ▼
[编排层 · 周复盘服务]
   │  缓存命中？→ 直接返回
   │  组装 Prompt + 安全策略
   ▼
[AI 网关（可选但推荐）]
   │  鉴权 / 限流 / 审计 / 模型路由
   ▼
[LLM 生成 Insight]
   ▼
[校验器]
   │  数字一致性 · 违禁词 · 长度 · JSON schema
   │  失败 → 降级（只出 Fact Card）
   ▼
[展示层]
   事实卡片（上）+ AI 洞察（下）+ 轻建议 + 反馈按钮
```

## 与现有微迹模块的关系

| 现有模块 | 复盘如何用 |
|----------|------------|
| `pages/records` | 增加入口与复盘结果页 |
| `utils/habit.js` | streak/完成态计算，生成 Fact |
| `utils/storage.js` | 读 habits/checkIns；缓存上周 insight |
| 今日打卡主路径 | **不侵入**；AI 不出现在打卡按钮上 |

## 关键设计决策

### 决策 1：事实与生成分离
- **选项**：A. 全交给模型算统计并写文案｜B. 规则出数 + 模型写文案
- **选择**：B
- **理由**：打卡对错必须可审计；模型擅长语言不擅长当账本
- **代价**：工程上多一层 Fact 构建与校验

### 决策 2：不做 Agent 工具调用
- **选项**：A. 模型可直接改习惯/代打卡｜B. 只建议，写操作需用户确认
- **选择**：B（MVP 甚至只建议、不提供写接口）
- **理由**：核心行为是「亲手打卡」；写权限是高风险
- **代价**：少一些「自动化魔法」，但品牌一致、风险低

### 决策 3：数据不足不调模型
- **选项**：A. 照样生成鸡汤｜B. 规则文案降级
- **选择**：B
- **理由**：无证据的生成 = 幻觉温床，且浪费成本
- **代价**：冷启动周 AI 存在感弱（可接受）

### 决策 4：隐私最小化上传
- **选项**：A. 上传全部原始 checkIns｜B. 只上传 Fact 统计 JSON
- **选择**：B
- **理由**：生成不需要精确到每条 id 的原始流水
- **代价**：未来细粒度叙事能力受限（v1 再评估）

## 失败态设计

| 失败 | 用户感知 | 系统动作 |
|------|----------|----------|
| 本周数据不足 | 「先打卡 2 天，再来看复盘」 | 不调模型 |
| 模型超时 | 仍看到本周数字卡片 | 降级；可重试 |
| 校验失败（数字编造） | 同降级 | 丢弃生成；记坏案例 |
| 超成本配额 | 「本周复盘已生成，可查看缓存」 | 只读缓存 |
| 用户关闭 AI | 仅统计卡片 | 尊重开关 |
