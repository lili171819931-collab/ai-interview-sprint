# 指标与评测：票易报

## 1. 北极星

**一次提交成功率（First-Pass Yield）**  
= 首次提交即通过的报销单 / 全部提交单  

它综合了识别质量、合规解释清晰度、用户补齐效率。

## 2. 产品指标分层

### 效率
| 指标 | 定义 | MVP 观察方式 |
|------|------|--------------|
| 准备时长 | 打开新建 → 点击提交 | 手动计时 / 后续埋点 |
| 票均处理时长 | 单票从上传到状态稳定 | 服务端时间戳差 |
| 导出使用率 | 导出 CSV/摘要次数 / 提交次数 | API 计数 |

### 质量
| 指标 | 定义 | 目标 |
|------|------|------|
| 金额事故 | 可提交金额与票面勾稽失败却未拦截 | =0 |
| 低置信混入率 | low confidence 进入可提交合计 | =0 |
| 人工改字段率 | 被编辑关键字段占比 | 下降趋势 |

### 体验
| 指标 | 定义 | 目标 |
|------|------|------|
| 驳回率 | rejected / submitted | 相对基线下降 |
| 重提成功率 | 重提单通过 / 重提单 | ≥70%（试点） |
| 有害反馈 | 「乱报金额」「伪称已验真」投诉 | ≈0 |

## 3. 评测集（建议维护）

黄金样例至少覆盖：
1. 抬头不一致  
2. 小票/收据  
3. 酒店超标  
4. 招待缺人数 / 人均超标  
5. 重复发票号  
6. 金额+税额≠价税合计  
7. 差旅缺返程（产品提示）  

每次改规则引擎先跑 `npm test` + 黄金集手工回归。

## 4. 上线闸门（Gate）

同时满足才可对真实用户试点：
- [ ] 金额事故 = 0（评测集）
- [ ] 低置信混入 = 0
- [ ] 审批摘要数字可追溯
- [ ] 未验真绝不展示「已验真」
- [ ] 隐私说明与数据留存策略明确
