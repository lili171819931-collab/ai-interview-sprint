# 项目故事 STAR：票易报 · 发票报销 Web

## 90 秒电梯稿

我做了一个可运行的发票报销 Web MVP「票易报」：员工上传发票后，系统自动归类并给出可报/限报/拒报，原因可解释，金额由规则引擎汇总，模型不能改账。  
产品上我把差旅、招待、月结、驳回重提做成情景模式；技术上把识别层和合规层拆开，保证财务可信。  
同域还沉淀了 WorkBuddy Skill 版 Prompt，证明同一套领域能力可以同时服务 Agent 与 Web 两种形态。

## STAR

### S 情境
中小团队报销仍大量依赖截图+表格，驳回多、解释弱；纯 AI 聊天能读票但难进审批闭环，传统费控又过重。

### T 任务
在有限时间内交付可演示的 Web MVP，并补齐产品文档，形成「能跑 + 能讲 + 能评测」的作品。

### A 行动
1. 用极致 Prompt 冻结 Must/Won’t 与类目、情景、CoT。  
2. 架构上强制：OCR 可错，账本不能错；金额用分；合规确定性。  
3. 实现主路径：上传→合规→提交→审批→导出，并做驳回重提。  
4. 写 PRD/架构/指标/旅程/竞品，对齐面试叙事。  
5. 用种子数据覆盖酒店超标、招待人均、小票拒报等关键样例。

### R 结果
- 可本地运行的 Next.js + Prisma + SQLite 应用  
- 合规单测通过；生产 build 通过  
- 完整产品文档与演示脚本  
- 与 WorkBuddy Skill 形成双载体作品集

## 追问预答

1. **为什么不只做 Chatbot？**  
   报销是多角色、强审计流程；需要状态机与导出，而不是一次性对话。

2. **AI 用在哪？**  
   字段建议与摘要生成；金额/去重/合规必须规则化。

3. **最大风险？**  
   金额幻觉与伪验真。用置信度门禁、未验真标记、测试闸门对冲。

4. **下一步？**  
   真实 OCR、制度配置化、验真 API、企微通知。
