# 市场调研：Mac 教学录屏（屏幕 + 圆形出镜）

## 1. 研究问题

「在 Mac 上录一段能发给学员的讲解视频」时，用户真正卡住的是什么？是编码格式、出镜形态、权限，还是工具过重？

## 2. 用户与场景

| 角色 | 场景 | 痛点 | 期望 |
|------|------|------|------|
| 独立讲师 / 知识付费 | 录网页操作 + 露脸 | 圆窗难控、成片浏览器打开像「网页视频」 | 本地 MP4、QuickTime 直接播 |
| 产品经理 | 录需求演示 / 评审回放 | 工具启动慢、云上传顾虑 | 开箱即用、数据不出本机 |
| 工程师教学 | 录 IDE / 终端 | 录进自己的控制窗、摄像头 Continuity 乱入 | 操作条不进成片、只用本机摄像头 |

## 3. 市场观察（定性）

1. **系统能力够用但不完整**：macOS 截屏快捷键强在静态/短录，弱在「圆窗出镜 + 麦 + 成片构图」。
2. **云原生录屏崛起**：Loom / Cap 等强调分享链接与 AI，适合协作，不适合「先本地成片再上传到自己的平台」。
3. **开源桌面录屏**：OBS 能力完整但心智重；Snapzy 类工具启发截图/快捷键体验，但非教学圆窗主路径。
4. **隐私敏感度上升**：教学素材含客户数据/未发布功能时，「默认上云」是拒绝理由。

## 4. 机会陈述

做一款 **macOS 本地优先的教学录屏壳**：

- 一句话：打开就能录「屏幕 + 圆形摄像头 + 麦」，停下来就是桌面上的 MP4。
- 差异点：所见即所得合成、录制中可操作的出镜小窗、操作条/监视窗不进成片、强制本机摄像头。

## 5. 不做的市场

- 多平台统一客户端（先把 Mac 体验打磨到可演示）
- 直播连麦 / 虚拟背景市场（虚化仅服务教学清晰度）
- 在线课程 LMS（本项目止于「成片生产」）

## 6. 验证方式（本项目）

- 本人真实录制讲解 → 检查 MP4 时长与操作条时长、圆窗位置、是否录进悬浮条。
- 权限失败 / Continuity / ffmpeg 缺失等异常路径有可读报错。
- 文档可支撑 5–8 分钟面试演示（见 `演示脚本.md`）。
